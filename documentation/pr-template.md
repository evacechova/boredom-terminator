# Pull request description

Use Summary and Acceptance criteria for every PR. Do not repeat the PR title in the body or add a separate verification section. Acceptance criteria use plain bullets without checkboxes; do not claim checks that were not performed.

Include Known limitations only when relevant, Screenshots for visual changes, and Preview when useful for reviewing the change. Use actual images and Vercel preview URLs; mark missing review material as pending and never substitute the production URL.

Approval, language, draft status, reviewer and merge rules are maintained in [AGENTS.md](../AGENTS.md).

```markdown
## Summary

Briefly describe the problem, resulting behavior and reason for the change.

## Acceptance criteria

- Describe an observable condition for accepting this change.

## Known limitations

- Describe a relevant limitation or deferred follow-up.

## Screenshots

Before: attach the previous UI.
After: attach the updated UI.

## Preview

Insert the actual Vercel preview URL.
```
